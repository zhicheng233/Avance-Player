# Avance Player

## Current state and entrypoints
- This is a single-project C# Avalonia desktop app. `Program.cs` configures the desktop lifetime and the console-only `--diagnostics` playback check; `App.axaml.cs` creates `MainWindow`; `MainWindow.axaml` hosts the navigation shell, the floating playback console, its three popovers (queue / sound / more), and typed page templates; `Views/ImmersiveLyricsView.axaml` is the full-window lyrics experience; `Views/FloatingLyricsWindow.axaml` is the separate always-on-top mini lyric window: it sizes itself to content (`SizeToContent="Height"`) and hides the lyric row entirely when `CurrentLyric` is null, so a track whose first line has not started yet shows just the header and seek bar instead of an empty gap; `MainWindow` re-anchors it to the screen bottom through `ContentSizeChanged` whenever that height changes.
- `MainWindow.axaml.cs` owns the in-window playback shortcuts (Space, Left/Right with hold acceleration, Ctrl+Left/Right, Up/Down, Ctrl+Alt variants), the tray icon/menu, close-to-tray behavior, and the animated immersive-lyrics exit. Space latches on the first `KeyDown` and only releases on `KeyUp`, so the OS auto-repeat cannot flip play state back and forth while the key is held; the arrow-key auto-repeat is intentionally left alone because hold-to-accelerate seeking relies on it. `Services/Input/GlobalHotkeyService` wraps SharpHook global hooks with a graceful fallback; `Services/SystemMedia/` publishes MPRIS on Linux, SMTC on Windows, and Now Playing on macOS, and routes OS commands back through `MainWindowViewModel`. `Services/SystemMedia/SystemMediaArtworkCache` gives those backends a readable file path for embedded artwork and non-JPEG/PNG sidecars by writing a cached PNG. The MPRIS path is verified on Linux; the Windows/macOS paths still need validation on those platforms.
- `ViewModels/MainWindowViewModel.cs` owns navigation, the playback rules (queue, shuffle history, repeat scope, A–B loop, sleep timer, speed), bilingual UI text, the immersive lyrics mode, lyric-file import, local-folder import into a playlist, state restore/save orchestration, and the UI playback clock. `Models/` contains music/playlist models (including a demo `BitrateKbps` used to derive the local quality tier), lyric lines/words, and parsed `LyricsDocument` metadata. The library starts empty and is populated by local-folder imports; demo tracks are no longer seeded. `Services/` provides English/Chinese strings, derives a warm, Monet-inspired UI palette from the current track's artwork seed (purple hues are deliberately remapped for the chrome), samples cover pixels in `Services/ArtworkPaletteExtractor.cs` for local tracks, contains the lyric parser stack under `Services/Lyrics/`, scans local folders in `Services/LocalFolderScanner.cs`, and contains the playback and persistence layers. The immersive `FluidBackdrop` uses the cover-derived `LyricsBackdropBase`/`LyricsBackdropAccent`/`LyricsBackdropSecondary` colours instead of the muted chrome palette; the empty placeholder falls back to the seeded palette.
- Playback is real for imported local files. `PlayerServices` is the composition root; `Services/Playback/PlaybackService` owns the current session and composes a `SwitchableAudioBackend` that routes absolute paths to `LibVlcAudioBackend` (LibVLCSharp + native libvlc) and relative demo paths to `SimulatedAudioBackend`. Queue/repeat/shuffle/A–B/sleep-timer rules stay in the view model. Backend events are marshalled to the UI thread and filtered by a globally unique playback session id. The 100 ms UI timer polls `PlaybackService.Snapshot`; backend-driven position updates must not call `Seek` (user drags, lyric jumps, and A–B wraps do). The console seek bar previews the pointer position locally (`SeekPositionSeconds`) and commits once on release, with an inset-aware hit area, so seeking inside the already-played region cannot be yanked back by the playback clock.
- Persistence lives in `Services/Persistence/`: `PlayerState` + `JsonPlayerStateStore` write `<LocalApplicationData>/AvancePlayer/state.json` atomically (with a `.bak` copy), `DebouncedStateSaver` coalesces frequent updates, and `LibraryRestorer` reloads tags/artwork/lyrics for saved absolute paths while silently ignoring legacy relative demo paths. The state stores library paths, playlist names/order, manual lyric-file paths, volume, last non-zero volume, shuffle, repeat mode, continuous speed, pitch-sync/pitch-offset preferences, EQ preset, language, floating-lyrics visibility, and the last track/position. Restore never autoplays; playback starts from the saved position on the first user play. Imported tracks are added to both the library and the target playlist so they survive restart. The equalizer preset is persisted and applied to local LibVLC playback.
- Local folder import and playback are the real library services: the playlist detail page's "Add local folder" button opens `StorageProvider.OpenFolderPickerAsync`, scans the selected tree recursively off the UI thread, deduplicates by file path, and appends tracks to the open playlist. Imported roots are remembered per playlist (`Playlist.FolderRoots` in memory, `PlaylistState.FolderRoots` on disk) so they stay live: `Services/FolderWatchService` watches each root with a recursive `FileSystemWatcher` (2 s debounce, plus a 2-minute count/last-write fingerprint poll as a fallback for network shares and filesystems without change notifications) and raises `Changed`, which the view model turns into `RefreshFolderAsync`. One root is scanned once per refresh and the result is applied to every playlist that references it. Tracks whose file no longer exists are dropped from the playlist and the library (judged by `File.Exists`, not by the scan result, so a failed tag read is not mistaken for a deletion); the currently playing track is dropped too without interrupting playback, because libvlc still holds the open handle. `InitializeAsync` calls `RefreshAllFoldersAsync` in the background so additions and deletions made while the app was closed are reconciled on startup. A path removed by hand from a playlist is remembered in `LibrarySettings.DismissedPaths` together with a size/last-write fingerprint, so a rescan does not bring it back — but replacing the file changes the fingerprint and lets it reappear. Playlists restored from state files that predate `FolderRoots` infer a root from the common ancestor of their track directories. `LocalFolderScanner` reads tags/duration/bitrate and embedded artwork through TagLibSharp, pairs sidecar covers (`cover`/`folder`/`front`/`album`/`artwork`, then the first image) and lyric files in the audio file's folder, samples the cover into a dominant/accent/secondary/background palette for the UI and immersive backdrop, and falls back to a lone lyric file only when the folder contains a single audio file. Supported audio extensions are MP3, FLAC, M4A, AAC, WAV, OGG, Opus, WMA, APE, ALAC, AIFF, DSF, DFF, and MKA. Sidecar lyric matching is case-insensitive so Windows-copied `.LRC` files work on Linux. `LoadTracksAsync` restores a known path list in order without re-scanning unrelated files; it shares the same `LyricsService` through `PlayerServices`.
- Song rows in the library/collection/playlist lists play on double-click; the per-row play button remains a single-click shortcut. The row background is an alpha-zero brush so the whole row is hit-testable, and the tap handler ignores taps that originate inside row buttons while also accepting native `DoubleTapped` gestures (with a duplicate-play guard), so playback does not depend on platform double-click counts. Apply hover transforms to the inner row content, not the row `Border`, so the pointerover hit area stays fixed; the same rule applies to category/playlist cards and lyric lines, whose Fluent template hover/pressed wash is explicitly suppressed.
- Animated backgrounds use an alpha-zero version of the target colour (for example `#001E1D19`) rather than `Transparent`: Avalonia's brush transition interpolates the RGB channels, and `Transparent` is white with zero alpha, which can flash light grey during a fade.
- Custom-drawn controls live in `Controls/`: `WaveProgressBar` (wavy seek bar plus the flat volume variant and A–B range markers), `FluidBackdrop` (soft animated colour field for the lyrics page), `TransportGlyph` (play/pause), `MediaGlyph` (skip, play, shuffle, repeat/repeat-one, queue, more, lyrics, plus/minus, close, fullscreen), `OptionGlyph` (menu sliders/speed/loop/clock), `VolumeGlyph` (monochrome speaker), and `LyricLineTextBlock` (smooth karaoke fill across timed words, plain step highlight for line-level lyrics). Prefer extending these over adding emoji glyphs or platform theme overrides.
- Motion is lightweight and timer-driven: a 33 ms ambient timer advances `AmbientPhase` for the fluid backdrop and wave; the 100 ms UI playback timer polls the active backend (the simulated demo backend advances on its own 50 ms clock); page navigation and now-playing track changes use `FadeSlidePageTransition` (fade plus a small rise/scale), the floating lyric line uses the same transition with a smaller offset, and popovers fade/rise/scale over ~200 ms. Hover states use `RenderTransform` transitions for lift/press feedback, the wave seek bar eases its fill and grows/shrinks the ripple and thumb halo through a small 16 ms motion timer, and glyph state flips pop. Lyric lines transition opacity/background/font size, the lyric list eases to the active line over 460 ms, and the immersive lyrics view plays a staged entrance (`Views/ImmersiveLyricsView.axaml.cs` + `Controls/Motion.cs`). Fullscreen changes still appear instantly. One-shot transform motion animates `Visual.RenderTransform` through a custom `ITransform` interpolator registered in `Controls/Motion.cs`; do not animate `TranslateTransform`/`ScaleTransform` children directly, because Avalonia's built-in transform animator only accepts a `Visual`.
- Lyric centring uses dynamic top/bottom margin on the `LyricsList` items panel (`MainWindow.axaml.cs`): a `ScrollViewer` offset clamps at zero/max, so the first and last lines need half a viewport of padding to reach the centre. Recompute the padding after resize, current-line changes, and imports; keep the nested background dispatcher posts so layout settles before measuring.
- Word-by-word lyrics are driven by `LyricLine.Words` + `CurrentWordIndex`; `LyricLineTextBlock` subscribes to those property changes and recolours `Run`s instead of rebuilding the visual tree every 100 ms tick. Bind its `Position`/`IsPlaying` properties to `CurrentPositionSeconds`/`IsPlaying`: a 16 ms control-local timer extrapolates the playback clock between 100 ms view-model updates and sweeps a per-run `LinearGradientBrush` across the current word, so word-timed text fills progressively instead of flipping at once. The control keeps one run per timed word, and the sweep gradient uses absolute coordinates fetched from `TextBlock.TextLayout` (`HitTestTextPosition` at the word's character offset), spanning exactly that word's own layout box — relative units are wrong there, because a text-brush gradient in Avalonia is laid out over the whole text rather than the `Run` that owns it, so every word would sweep the full line width at once. Also do not estimate the span with a second `FormattedText` pass — font fallback and shaping differ from the rendered layout and the gradient bleeds into neighbouring characters. Line-level formats (plain LRC/SRT) have no per-word timing, so they do **not** animate: they keep a single `Run` and flip between the unsung and future colour the moment `line.Timestamp` is reached (`position >= line.Timestamp.TotalSeconds ? sung : future`). A whole-line fitted sweep was removed on purpose — it cannot know where the vocals are, and in practice it read as the highlight splitting into separate segments; do not reintroduce a whole-line gradient. The boundary colour must never be darker than the sung colour: `AccentBrush` is sampled from the cover art and is usually darker than the warm-white sung colour, so using it raw as the mid stop makes each swept word collapse into a narrow dark band that reads as a separate second segment. `LiftAccent` falls back to the sung colour when the accent is not brighter. Keep `LyricLine.Text` equal to the concatenation of its words for the floating-window fallback and accessibility.
- `Avance-Player.csproj` targets `net10.0` and references Avalonia 12.1.4 (Fluent theme, Inter font), TagLibSharp 2.3.0 for local metadata and embedded artwork, and LibVLCSharp 3.10.2 for local playback. LibVLCSharp is only a binding; a native libvlc runtime must be installed separately on each platform. Keep simulated demo playback clearly separated from the real folder-scanning/lyrics/audio services.

## Build and verification
- .NET SDK 10.0.402 is installed under `~/.dotnet`, but `/usr/bin/dotnet` resolves to a separate SDK 9 installation. Use `~/.dotnet/dotnet build Avance-Player.slnx` (or put `~/.dotnet` first on `PATH`); run with `~/.dotnet/dotnet run --project Avance-Player.csproj` in a desktop session.
- There are currently no tests, lint scripts, CI workflows, or pinned SDK in this repo. Do not lower `net10.0` to work around the system `dotnet` path selecting SDK 9.
- Local playback requires native libvlc. Linux uses the system libvlc package (the development machine has it); Windows/macOS builds reference `VideoLAN.LibVLC.Windows` / `VideoLAN.LibVLC.Mac`, which bundle the native runtime conditionally. `LibVlcRuntime` also checks `AVANCE_LIBVLC_PATH` and app-local `libvlc` folders, fails gracefully when initialization is unavailable, and local-file playback reports a bilingual error instead of crashing.
- Run `~/.dotnet/dotnet run --project Avance-Player.csproj -- --diagnostics` for a console-only LibVLC check (version, audio outputs/devices, filters) without starting Avalonia. It is the quickest way to validate a native runtime or audio device on a headless/remote machine.
- Publish profiles live in `Properties/PublishProfiles/` (`win-x64`, `osx-x64`, `osx-arm64`, `linux-x64`, `linux-arm64`). They publish self-contained by default with single-file publishing and trimming disabled; pass `-p:SelfContained=false` for a framework-dependent publish. Linux output still expects the system `libvlc` package.
- Offscreen UI checks: an Avalonia.Headless + Skia harness outside the repo (`/tmp/opencode/avance-preview`) renders the main window, popovers, lyrics page, compact width, and floating lyrics window to PNGs. It references the project and must be rebuilt (`~/.dotnet/dotnet build`, then `~/.dotnet/dotnet run --no-build`) after UI changes. Use it instead of desktop screenshots on Wayland/Xwayland sessions. A smaller harness (`/tmp/opencode/lyrics-ui-check`) reports first/middle/last lyric centring, word run colours, and imported TTML frames. `/tmp/opencode/folder-scan-check` builds synthetic nested folders (WAV/MP3, cover images, LRC sidecars) and checks recursive scanning, metadata, artwork, and lyric attachment; `/tmp/opencode/folder-ui-check` drives the view-model import path and renders the playlist state. `/tmp/opencode/backend-check` exercises LibVLC (using `--aout=dummy`), simulated playback, JSON state, library restore, and the view-model playback/restore clock; it needs a small WAV argument.
- Parser fixtures: the AMLL TTML database (`https://github.com/amll-dev/amll-ttml-db`) is useful for real TTML/QRC/YRC/LYS/LRC samples, but its lyric text is copyrighted. Use it for local inspection only; commit synthetic fixtures, not downloaded songs. The parser smoke harness lives at `/tmp/opencode/lyrics-check`.
- Localization check: every `Text[Key]`/`Text.Format("Key", …)`/`SetStatus("Key", …)` key in XAML and C# must exist in both dictionaries in `Services/LocalizedText.cs`; a quick scripted diff between XAML keys and the two dictionary blocks is the fastest guard.
- UML diagrams live in `docs/uml/` as Mermaid `.mmd` sources plus rendered PNGs (`01` models/view models, `02` services/composition root, `03` lyric parsers, `04` system media, `05` playback records, `06` windows/custom controls, `07` localization/palette/hotkeys/converters). Edit the `.mmd`, then run `docs/uml/render.sh` (needs the mermaid-cli setup described in `docs/uml/README.md`); each diagram pins `config: layout: elk` because the default dagre layout stretches large class diagrams into unreadable columns or hangs.

## Product scope and remaining work
- The prototype demonstrates OOP music/playlist models, library browsing, playlist edits, playback controls/history, bilingual UI (English/Chinese), cover-derived theme/backdrop colors, a floating playback console with queue, quality/EQ/speed, A–B loop, sleep timer, play order, loop scope, volume and floating lyrics, a full-window synchronized lyrics view with manual lyric import, recursive local-folder import with tags, covers, and sidecar lyrics, keyboard/global playback shortcuts, a tray icon with playback/show-hide/quit controls, and OS media integration (MPRIS/SMTC/Now Playing). Local import, local playback, local equalizer processing, state persistence, conditional Windows/macOS native runtime references, and per-RID publish profiles are in place; the simulated backend remains available for tests and legacy relative sources but the app no longer seeds demo tracks. The remaining production gaps are installer packaging, Windows/macOS media-control validation, and broader codec/device testing.
- Lyric support: TTML (Apple/AMLL word timing, inline `x-translation`/`x-roman`/`x-bg`, metadata translation tables), LYS, QRC (plain/decrypted), KRC (plain and XOR+zlib encrypted), YRC, LRC/ESLRC (including enhanced `<mm:ss.xx>` word tags and `offset`), ASS/SSA (karaoke `\k`/`\kf`/`\ko`, translation/romaji dialogue pairing), and SRT. Plain LRC/SRT are line-level by nature. Encrypted QQ Music QRC is detected and rejected with a clear message rather than decoded. Text encoding detection tries BOM, strict UTF-8, then GB18030 and Shift-JIS (the kana count decides when both decode).
- Quality and backend boundaries: audio quality remains a UI-only read-only "bitrate · tier" label derived from TagLib metadata or the demo metadata, not a decoded audio probe; the settings subtitle says so. The equalizer, continuous speed, pitch-sync toggle, manual pitch offset, volume, sleep timer, play/pause, stop, seek, and A–B loop are real for local files. Manual pitch offset bypasses libvlc 3's public API: `Services/Playback/LibVlcNative.cs` binds `var_Create`/`var_Set` from libvlccore so the backend can write `audio-filter` and `pitch-shift` on the MediaPlayer's native handle, then rebuild the audio output and reload the media (a playing aout is owned by the input and will not pick up a new chain). The filter chain is space-separated, so the equalizer and `scaletempo_pitch` coexist as `"equalizer scaletempo_pitch"`; the chain has to be rewritten after `SetEqualizer` because `libvlc_media_player_set_equalizer` overwrites `audio-filter` with `"equalizer"`, and changing the equalizer while pitch is active requires a reload. Measured: +12 semitones turns a 999.5 Hz sine into 1999.5 Hz. `SupportsPitchShift` is only true when the libvlccore interop resolves and `LibVLC.AudioFilters` actually contains `scaletempo_pitch`; otherwise the offset stays a stored preference and the UI says the backend cannot apply it. The pitch-sync toggle disables LibVLC's `--audio-time-stretch` and is functional. The equalizer compensates LibVLC's internal `EQZ_IN_FACTOR` of 0.25 with a 12 dB preamp (LibVLC's own `equalizer-preamp` default) so non-Flat presets are not 12 dB quieter than Flat, normalizes the curve around its average, and keeps 3 dB of peak headroom on the loudest band so a Bass-style preset cannot clip a full-scale master. Keep that honesty when extending the prototype.
- Keep the Material + island-inspired Avalonia UI, fluid ambient background, and animated lyric highlighting; do not copy reference-image assets or introduce Windows-only WPF APIs.
- The bilingual toggle depends on `LocalizedText` raising `"Item"` (Avalonia indexer bindings) as well as `"Item[]"`; keep both when changing the notification plumbing. Avoid setting `Opacity` on containers whose text must stay legible (it fades children too); use an ARGB background instead.
- `TextBlock` clips glyphs to its own bounds. A custom `LineHeight` can leave the last line's descenders outside those bounds (the English hero headline did); set `ClipToBounds="False"` on such a block rather than removing the tight line spacing.

## C# style and design references
- Follow this repo's file-scoped namespaces and same-line opening braces for new code. The author's other projects do **not** share one brace convention (`WhereMyWinCursor` uses same-line; `PN532-Aime-Reader` uses next-line); favor local consistency over assuming a global style.
- For substantive work, consult the author's C# code at https://github.com/zhicheng233: `WhereMyWinCursor` separates typed config/persistence and XAML/ViewModel UI state; `PN532-Aime-Reader` isolates device I/O behind an interface with a replay implementation. Keep library/playback logic out of Avalonia window code-behind and isolate the eventual audio backend; do not import Windows-only WPF APIs.
